# Video runtime adapter

This adapter is available ONLY when the user explicitly enables generated motion video (motion_video_authorized=true, delivery_kind=video_edit) and selects a video connection. Default production is a still-image animatic using codex-imagen. A video reference or person reconstruction request never opts into this adapter. It removes the previous universal motion-generation ban; it does not change still-image provider choice or grant publication rights. Never submit video through an arbitrary shell command: the service `video` gateway owns quotes, approvals, submission reservation and results. Use installed authenticated Higgsfield CLI without extracting credentials or changing its config.

## Operation contract

Call the absolute `tool_client.py` path supplied by the current runner with the `video` operation and JSON stdin. It is packaged alongside the Python backend; do not assume an original Studio app checkout.

- `{"operation":"models"}` lists actual video models.
- `{"operation":"inspect","model":"hf_mult_replace_object"}` fetches its current schema.
- `{"operation":"quote","items":[{"label":"source interval and purpose","model":"actual model","params":{"resolution":"720p","prompt":"full replacement instruction","image_references":["references/actual.png"],"video_references":["07_VIDEO_INPUTS/actual_segment.mp4"]}}]}` estimates the ENTIRE bounded plan. Every item uses current live fields and actual local source files. At most30 items; retries0. The gateway returns aggregate credits and a quote_id. This may upload references but never generates a job.
- `{"operation":"submit","quote_id":"returned ID","index":0}` executes ONLY the displayed, user-approved quote item, once. No direct `higgsfield generate create`, no rewritten params, no extra outputs, no automatic retries. The gateway rechecks the current price and input hashes. Existing submitting/uncertain/failed/result states are returned without another charge.
- `{"operation":"status","quote_id":"returned ID"}` returns batch state; add index to inspect an actual saved provider response. A response_received state is not proof of completed video: inspect the provider's actual terminal status and fetch/view the actual media. If submission outcome is unknown, reconcile the existing job instead of submitting again. Preserve actual job IDs in canonical/history joins.

After quote, tell the user what the edit will change, count, resolution and aggregate quoted credits. Finish normally awaiting_input. The terminal shows the quote through /status; the user explicitly confirms it through /approve-video <quote-id>. The service records that bounded approval outside the agent workspace. Do not use block for missing budget approval. Never invent approval or consume free generations unless the user explicitly chose them. A changed plan/input requires a new quote.

## Reference-video character replacement

Use the actual current replacement-capable model, not text-to-video from a lookalike prompt. Provider duration bounds vary; inspect the current model schema and actual accepted input limits rather than assuming cached bounds. Inspect actual source metadata and frames, plan suitable intervals and verify encoded interval durations BEFORE quote. Long originals need supported segments and reassembly. Preserve source shots, lighting, camera, clothes, product inserts, text and sound unless the user requests changes. If only person shots need edits, reuse unaffected source footage; do not pay to regenerate unrelated shots. For very short shots, group/pad with explicit trim-back records; never silently lose or duplicate content. Preserve every identity reference supplied for the current request; an identity sheet is an input, not automatic acceptance.

Do not confuse reconstruction with a guarantee of pixel-exact deepfake or unchanged optical motion. Report actual inspection and remaining limitations. No new narration is required merely because this app also makes narrated animatics. Preserve original music/audio where authorized and actually present. Do not add captions unless requested or already present.

## Task-specific video-edit delivery

When the current request is an actual edited video (not a narrated still animatic), call configure with delivery_kind=video_edit and appropriate measured target/aspect. This explicit profile leaves the original animatic validator unchanged. The user’s global scene/cut storyboard and first/last-frame handoff requirement still applies to video edits under production contract v2. Build the actual sheet(s) from inspected source/final frames, map all actual cuts including preserved product shots, and record camera, timing and independently usable endpoint prompts. This is non-generative documentation, not permission for extra paid images. A replacement request does not need an invented screenplay, new narration or invented subtitles. Existing project.json remains the sole creative ledger. Follow recording-production-history for actual operations and keep previous blockers as history, not current capability.

Write 10_DELIVERY/render_result.json with kind=video_edit, video, sha256, video_quote_id, generation_results=[{index,provider_job_id,file,sha256}] for every approved item. Actual completed provider media must join the reserved gateway result; job IDs/URLs alone are not local assets. Register the final asset and delivery_spec.final_asset_id in canonical project.json, preserve source-to-segment/edit joins and actual history. Do not hand-edit the service's private quote records.

Write 09_QA/qa.json with video_sha256 and checks for identity,visual,continuity,playback,timing,audio,captions. Every check includes actual observed evidence; N/A is justified only for genuinely absent audio/captions. Identity includes each edited interval and representative full-size frames, not only thumbnails. Validate product/typography preservation, joins, color and temporal continuity. Check actual audio preservation; unchanged PCM hashes can establish preservation but not a new direct-listening performance review. Parent playback inspection must describe its actual scope. Never claim perceptual observations unsupported by your runtime. Save a reviewable draft if observation is blocked, preserve all completed media, and report the precise remaining observation rather than claim an unsupported completed review.

For contract v2, complete and validate 06_GENERATION_SPECS/production_handoff.json against actual canonical shots as described in PRODUCTION_HANDOFF.md. First/end prompts remain usable for later revisions while actual source/output observations are recorded separately. Only then call agent_finish validate_delivery. The server independently checks the actual file/hash/duration/full decode, required QA evidence, approved job/input joins, canonical final asset and history before exposing completion. Google archive uses the validated result when selected. Publishing is outside this adapter.
